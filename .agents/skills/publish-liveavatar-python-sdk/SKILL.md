# 发布 LiveAvatar Python SDK

本 skill 可整体复制到任意支持 SKILL.md 的工具。脚本路径相对于本文件，不依赖安装位置、用户名、Codex API 或固定仓库目录。

只发布已经准备好的版本。不得自动修改版本、changelog、业务代码，或提交、推送、打 tag。只使用正式 PyPI。

## 确认仓库和环境

1. 从当前工作目录向上查找 `pyproject.toml`，检查项目包名为 `liveavatar-channel-sdk`。找不到或项目不匹配时询问仓库路径，不扫描整个电脑或猜测个人路径。
2. 阅读适用的仓库指引、项目构建配置和中英文 changelog。查看 Git 状态；若发布内容包含未提交变更，说明内容并取得用户确认。不自动清理或提交。
3. 使用满足项目 Python 要求的虚拟环境，不修改全局 Python。可复用项目环境，或用选定解释器执行 `python -m venv <环境目录>`。macOS/Linux 的解释器通常位于 `bin/python`，Windows 位于 `Scripts/python.exe`。后续始终显式使用同一解释器，不能假设 shell 激活状态跨调用保留。
4. 在仓库中用该解释器执行 `-m pip install -e ".[dev]" build twine`。按实际项目配置调整测试依赖。缺少解释器或安装失败时报告原因，不绕过测试。

下文 `<python>` 表示选定虚拟环境解释器，`<skill>` 表示本文件所在目录，其他尖括号是待替换参数。使用宿主 shell 的正确引号处理空格路径。

## 构建可审核的产物

运行随附的标准库脚本（脚本本身不安装依赖、不上传）：

```text
<python> <skill>/scripts/release.py prepare --repo <仓库路径> --version <预期版本>
```

没有指定版本时省略 `--version`，读取构建元数据。脚本会执行 pytest、在系统临时目录中构建全新的 wheel 和 sdist、执行 twine check、核对两个包的名称和版本、确认该版本尚未出现在正式 PyPI，最后输出 `release.json` 及产物信息。动态版本由构建后元数据确定。网络失败不会当成版本不存在。

执行仓库明确要求的额外发布检查。失败则停止并报告；不修复无关代码。面向提交的版本递增脚本不是再次递增发布版本的理由。保留产物供审阅，不删除既有 dist 文件。

```text
<python> <skill>/scripts/release.py check <release.json路径>
```

向用户展示包名、版本、正式 PyPI 上传地址、两个产物的绝对路径/大小/SHA-256、测试结果及清单 SHA-256。询问是否上传这些产物，随后等待回答。最初的“发布”请求不替代本次产物确认。

## 确认后上传

使用环境变量 `TWINE_PASSWORD` 中的 PyPI API token，不需要个人账号信息。不索要聊天中的 token，不把 token 写入命令参数、文件或日志，也不输出变量值。

先再次运行 `check`，将清单哈希与用户批准时的值比较。清单或产物变化必须重新展示并确认，不能静默重建。

获得确认后，按以下顺序取得上传环境：

1. 当前助手进程已有 `TWINE_PASSWORD` 时直接使用。
2. 当前进程没有时，检查操作系统的用户级环境以及用户配置的交互式 shell 环境。检查只能报告变量是否存在，不得打印或把值返回给助手。如果该环境中存在变量，在同一个能读取它的子进程中执行上传；不要把 token 搬运到命令文本、临时文件或日志。macOS 上可检查 `launchctl` 用户环境，并可通过用户配置的交互式 shell 加载其正常启动环境；其他平台使用等价的用户级环境机制。不得假定 `.zshrc` 或其他特定文件一定存在。
3. 前两处都没有时，可读取仓库根目录的 `.env`，但必须先确认该文件已被 Git ignore、未被 Git 跟踪且未被暂存；任一条件不满足就拒绝从中读取并说明风险。只把 `TWINE_PASSWORD` 作为数据解析，不得 `source`、执行或导入整个 `.env`，不得输出解析值。建议检查文件权限仅允许当前用户读取；权限过宽时先要求用户收紧。skill 不得创建 `.env`、写入或修改 token。读取后只把值传给执行 Twine 的同一子进程，并在进程结束时丢弃。
4. 以上位置都没有时，提供适配当前交互式终端和 shell 的一次性隐藏输入方案。用户输入不得回显或进入历史记录；只导出到该终端进程，运行精确上传命令后立即清除。不要让用户把 token 发到聊天里。明确说明这一步由用户在交互式终端执行，随后由助手运行远端验证。

变量可用后，用精确产物路径执行：

```text
<python> -m twine upload --non-interactive --repository-url https://upload.pypi.org/legacy/ --username __token__ <wheel绝对路径> <sdist绝对路径>
```

`__token__` 是固定认证标记，不是个人账号。不要用通配符、`--verbose`、`--skip-existing` 或 TestPyPI。脚本故意不包含自动上传步骤，防止构建动作直接触发发布；上传命令由助手在用户确认后单独执行。

## 发布验证与失败处理

```text
<python> <skill>/scripts/release.py verify <release.json路径>
```

该命令检查远端名称、版本、文件名及 SHA-256。可见性延迟可有限重试查询，不能因此重新上传。上传成功但校验失败时准确区分“上传成功”和“验证未完成”。

上传超时、失败或部分成功时先查询远端状态，不盲目重试整批文件。若需补传，核对已存在文件哈希，展示缺失文件并重新取得确认，仅补传缺失文件。状态未知或哈希冲突时停止，不删除远端发布或自行换版本。

最终报告实际完成阶段、产物位置以及验证成功后的 PyPI 版本链接。只有准备完成时不得宣称发布成功。
